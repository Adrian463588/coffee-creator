## Confirmed source findings and defects

1. **D-001 — P0 fabricated-measurement/evidence risk.** Green QC initializes moisture `10.8`, water activity `0.585`, density `710.0`, meter/serial, and measured flags as prefilled local UI state (`SensorySprint04Screens.kt:2708–2763`). Pro Operations also displays hardcoded panel/score/citation-like values (`:3505–3556`). These values have no user measurement or source provenance. This conflicts with S4-045/046/051/057 and the domain’s `NOT_MEASURED`/`UNKNOWN` policy.
2. **D-002 — P1 false success for lock/export.** CVA lock creates a UUID substring labelled SHA-256 (`:1470–1475`); CVA JSON/CSV buttons only set a notice (`:1496–1511`); Green QC computes a local JSON/CSV string, discards it, then reports export (`:3420–3438`); Operations hashes a dummy literal (`:4382–4404`). These are reachable app actions, not test-only code.
3. **D-003 — P0 Sprint 04 persistence gap.** New S4 forms and operations hold data in Composable local state. `CoffeeApp.kt:6330–6356` supplies no ViewModel or persistence callbacks. “Log to Brew Journal” only sets a success string (`SensorySprint04Screens.kt:1441–1445`). Existing legacy cupping remains separately ViewModel-backed and should be preserved.
4. **D-004 — P1 old nested JSON compatibility.** Room v2 stores record JSON. `ChatMessage.sourceChunkIds` was added with a Kotlin default, but Gson-decoded older records may omit it; backup validation dereferences it. Schema-v2 backup migration adds only the top-level `estimates` collection and expects current nested shapes. Existing v2 backup regression fixture has no recipe/chat rows. Data loss was not observed; older records can become inaccessible or restore may reject them. Evidence: `Models.kt:389`, `DataRepository.kt:377`, `BackupCodec.kt:98,124,234–242`, `RecoveryRegressionTest.kt:26`.
5. **D-005 — P1 real BLE absent.** Current UI calls `connectMockScale()` and uses `SimulatedBleScaleDriver`; no production GATT implementation/permission was found. Mark S2-032..036 and physical scale behavior BLOCKED, not PASS.
6. **D-006 — P1 timer recovery caller not found.** `exportBrewSessionSnapshot` and `restoreBrewSession` are present, but repository/lifecycle persistence callers were not located. Add a process-death/relaunch regression before claiming recovery.
7. **D-007 — P1 BR-17 acceptance conflict.** `DripperIntelligenceModels.kt:124` remains `PENDING_VIDEO_REVIEW`, and Sprint 03 states the video transcript/content could not be verified. `TASKS.md:100` marks BR-17 complete. Timestamped source evidence is absent.
8. **D-008 — P0 standards-conformance block.** Sprint 04 requires `CVA_FIELD_MAPPING.md` and a verified mapping before exposing production `SCA_CVA_CURRENT`; this file and the mandated source/gap registers are absent. Code labels the protocol current and uses a descriptive intensity range 0–5; the official SCA materials identify standards SCA-103 and SCA-104 and SCA education materials describe 15-point descriptive and 9-point affective tools. Exact current field mapping/license was not independently verified because the SCA PDF endpoint was not fetchable in this research pass. Until validated, production standards-conformance claims are BLOCKED; custom research mode should be explicit.
9. **D-009 — P1 RAG evidence conflict.** `TASKS.md:109–110` says last Android direct-facts result was 39/40 and later host 40/40 is not Android proof; `docs/VERIFICATION.md:15` records a 40/40 device candidate. No bound current commit/build/device receipt resolves the discrepancy.
10. **D-010 — P1 real photo OCR acceptance open.** Photo picker/camera and bundled OCR code plus synthetic image tests exist. The OpenSpec task list still leaves real bag-photo acceptance unchecked; no real coffee label was tested in this audit.
11. **D-011 — P1 consent default.** Pro Operations initializes sharing consent to `true` (`SensorySprint04Screens.kt:3567`); the required positive user-consent interaction is not evidenced before export.
12. **D-012 — P1 missing content provenance register.** Sprint 04 mandates source/license/version evidence for all content. Lesson source links exist, but the required `SENSORY_CONTENT_SOURCE_REGISTER.md` was not found; content-level rights and factual provenance are therefore incomplete.
13. **D-013 — P0 historical recipe corpus reconciliation.** The v1.9.5 production catalog/test were removed in v1.9.6, similar recipe-shaped content moved to a synthetic test fixture, and current champion templates have not been reconciled by stable historical ID or provenance. This establishes a source-history gap, not loss of installed user records; see `LEGACY-10` and `FEATURE_PRESERVATION_DIFF.md`.
14. **D-014 — P1 v1.14.5 download metadata mismatch.** The release asset API reports 123,036,057 bytes and the canonical `Adrian463588/coffee-creator` repository; `docs/releases/v1.14.5.md` reports 123,039,143 bytes and uses `murchid21/CoffeCreator` in its curl command. The asset digest recorded in the release metadata is `447ccdde1cafc1799bb6a11af4e4c32a1344a4e11708beea64ec1fc2621a0f09`.
15. **D-015 — P0 published behavior claims conflict with tagged source.** Public v1.14.3 notes claim instrument-grounded Green QC readings and SHA-sealed exports, and v1.14.4 notes claim persisted Sprint 04 records, verified restore, and journal logging. The corresponding tagged source still contains prefilled values/pseudo-hash and local-only form state. No commit-bound device receipts were found for those claims.

## Preservation and specification conflicts

- Routes: all nine current NavHost destinations are present. Comparing `v1.13.1..v1.14.5` under `app/src/main`, `app/src/test`, `app/src/androidTest`, and `app/src/sharedTest` showed additions/modifications for Sprint 04 but no deleted source/test paths. The `v1.14.5..HEAD` delta is README/screenshots/OpenSpec documentation only; no app code changed after the release tag. This establishes file-level preservation for those comparisons, not semantic preservation of every record or user journey.
- The progression tags indicate Sprint 02 epics in `v1.3.0`–`v1.9.0`, Sprint 03 in `v1.13.0`, and Sprint 04 epics in `v1.14.0`–`v1.14.4`; `v1.14.5` is a UI/README refinement. No named Sprint 01 specification was located; FR-01..10 in PRD are its source.
- **SPEC_CONFLICT-01:** Sprint 03 header says the implementation is “NOT implemented or tested”; current code/tests and TASKS completion claims exist. Current source wins for inventory; neither old header nor checked boxes establish acceptance.
- **SPEC_CONFLICT-02:** TASKS says RAG Android retest remains failed at 39/40 while `docs/VERIFICATION.md` reports 40/40 candidate. They differ in acceptance layer and are not reconciled for current HEAD.
- **SPEC_CONFLICT-03:** TASKS marks BR-17 complete, while source/spec keep it pending until timestamped review.
- **SPEC_CONFLICT-04:** S4 mandates a full current field map and forbids unverified current-standard labeling. The code’s `SCA_CVA_CURRENT` name/ranges exist without the required mapping artifact. No silent interpretation is accepted.
- Best-practice guidance includes web React/Tailwind examples that do not transfer literally to Compose. The native Material 3 rules in `DESIGN.md`, Android UX requirements, and accessibility invariants govern implementation.

## External standards and research sources

The page reserves copyright. Download availability is not an app redistribution or form-reproduction license.
