# Proposal: UI Refinement, Custom Brew & Bean Inputs, and Curated Coffee Library & Journal Dataset

## Problem Statement
The existing Brew interface bundles sections in a 2-row wrapped chip layout, creating cognitive overload and friction during rapid recipe formulation. In addition, coffee beans and brew methods are constrained to pre-selected lists without direct custom text input fields, preventing baristas from entering custom lots or unique brewing apparatus directly in the recipe form. Finally, the initial library and brew journal lack pre-populated, verified world-standard coffee recipes, real specialty coffee origins, and sensory tasting logs.

## Proposed Solution
1. **Brew Section Tabs Refactoring**:
   - Separate menu cards with single-row scrollable chips (Recipe, Measurements, Ingredients, Tools).
   - Dedicated card hierarchy with tactile feedback and zero-pain-point UX.
2. **Custom Bean & Brew Method Input**:
   - Provide direct input fields for custom coffee bean and custom brew method in the recipe builder.
   - Automatically persist custom coffee beans to the local library repository with valid metadata.
3. **Curated, Validated Dataset**:
   - Populate high-quality, verified coffee recipes (James Hoffmann V60, Tetsu Kasuya 4:6, Wendelien van Bunnik AeroPress, Scott Rao Chemex, French Press, 9-Bar Espresso, Kalita Wave, Moka Pot, Cold Brew).
   - Populate authentic specialty coffee beans (Ethiopia Yirgacheffe, Colombia Pink Bourbon, Panama Geisha, Kenya SL28, Indonesia Aceh Gayo, etc.) with verified agricultural metadata.
   - Populate authentic brew journal entries with real extraction measurements, tasting notes, and sensory observations.
4. **Modern 2026 UI/UX Polish**:
   - Apply 4pt/8pt spacing geometry, concentric border-radii, tactile micro-feedback, and WCAG 2.2 AA contrast.
   - Refactor Home quick navigation from wrapped tonal buttons into a structured, tactile grid with distinctive icons.
